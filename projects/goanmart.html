01 — The Problem

Local sellers had no lightweight way online.

Small sellers in Tier-2/3 markets are largely locked out of e-commerce: existing platforms are built for large catalogs and national logistics, not a single seller with a handful of products and a local buyer base. GoanMart started as an attempt to fix that — a marketplace light enough for one seller to run, with real-time communication instead of a support ticket queue.

The product vision

Rather than one generic storefront, GoanMart is built around three cooperating roles — Admin, Seller and Buyer — each with its own dashboard, permissions and workflows, all sharing a single backend and data model.

03 — Role-Based System & Auth

Three roles, one backend.

Admin, Seller and Buyer each get a distinct dashboard and permission set, but they're served by the same Express application and MongoDB instance. Role checks happen at the middleware layer before any controller logic runs, so a Buyer request can never reach Seller-only routes regardless of what the client sends.

Authentication

Access is controlled with JWT access tokens plus refresh tokens, so sessions stay short-lived without forcing constant re-logins. Every one of the 67 endpoints sits behind this layer — there's no unauthenticated write path anywhere in the API.

04 — Real-Time Communication

Seller ↔ Buyer chat over Socket.io.

Instead of routing every question through support tickets, buyers message sellers directly in a real-time thread backed by Socket.io, with delivery falling back to Firebase Cloud Messaging push notifications when a user is offline. This was one of the trickier pieces to get right — reconnection handling and message ordering across dropped connections needed real edge-case testing, not just the happy path.

05 — The AI Layer

LLMs as product features, not gimmicks.

Two LLM-backed features ship in production: a product recommendation engine that surfaces relevant listings based on browsing and purchase signals, and voice ordering, which lets buyers place an order by speaking instead of navigating menus. Prompt engineering was also used throughout development itself — accelerating debugging, boilerplate and documentation — but the two features above are the parts users actually touch.

06 — Payment Architecture

Razorpay, wired end to end.

Checkout runs through Razorpay for payment collection, with Cloudinary handling product and listing media so the API layer never touches raw file uploads directly. Order state transitions (placed → paid → fulfilled) are tracked server-side so a failed or pending payment can never silently mark an order complete.

07 — Performance

~40% faster loads.

Frontend performance work centered on React Query for server-state caching (cutting redundant refetches) and Vite's build pipeline for smaller, faster-loading bundles. Together these changes cut measured load times by roughly 40% compared to the earlier build.

  • React Query for caching and de-duplicating API calls across dashboards
  • Vite for faster builds and smaller production bundles
  • Indexed MongoDB queries on high-frequency read paths
08 — Engineering Challenges & Decisions

What was hard

  • Keeping three roles' permissions consistent as new features were added — a missed check in one route could leak Seller data to Buyer views.
  • Real-time messaging reliability across reconnects and background tabs.
  • Balancing AI feature latency (recommendations, voice ordering) against page load budgets.

Decisions I'd defend

  • One MongoDB instance with role-aware schemas over separate databases per role — simpler to reason about, easier to keep consistent solo.
  • JWT + refresh tokens over session cookies, for a mobile-friendly API surface.
  • Modular MVC services instead of a single monolithic controller file, so features stay isolated as the codebase grows.
09 — Lessons Learned

Shipping solo means every shortcut becomes technical debt you personally have to repay.

Building and operating GoanMart alone forced discipline that a team would otherwise enforce — writing Postman tests before merging, auditing routes for dead code, and treating performance regressions as bugs, not later cleanup. The biggest lesson: a role-based system needs its permission model designed early, because retrofitting it later touches almost every route.

10 — What's Next

Next improvements

  • Formal caching layer (Redis) for the highest-traffic read endpoints — not yet implemented.
  • Automated end-to-end test coverage alongside the existing Postman suite.
  • Expanding the recommendation engine with more purchase-history signal.
